# 10-Work/ — 本职工作

> 你的本职工作产生的一切文件。

## 状态分层（用目录前缀 `_` 控制可见性）

```
10-Work/
├── _Active/        ← 🔥 正在做（活跃项目，随时打开）
├── _Hold/          ← ⏸️  暂停（暂时搁置，可能回来做）
├── _Reference/     ← 📋 常用参考（模板、规范、SOP、非项目文档）
├── _Completed/     ← ✅ 刚结束（偶尔要翻，3月不动→Archive）
└── 99-Archive/     ← 🗄️ 归档
```

### 状态流转规则

```
新项目 → _Active/
           │
    做完或搁置？
     ├── 暂停 → _Hold/
     ├── 完成 → _Completed/ → 3月不动 → 70-Archive/[年份]/
     └── 取消 → 99-Archive/
```

| 状态 | 判断标准 | 最多放几个 |
|---|---|---|
| `_Active/` | 最近 2 周内打开过 | ≤ 5 个（超过说明精力太分散） |
| `_Hold/` | 暂停但未来可能继续 | ≤ 10 个 |
| `_Reference/` | 非项目的工作资料 | 不限 |
| `_Completed/` | 已完成，偶尔翻 | 超 3 个月不碰 → 70-Archive/ |

### 为什么用 `_` 前缀
- `_` 开头的目录排在所有项目前面（文件管理器默认排序）
- 状态层永远是第一眼看到的东西
- 项目目录名不带任何前缀，保持简洁

## 项目命名规范
- 简洁功能描述，不加日期不加编号
- `SegGrade-Model` ✅ / `202608-SegGrade-Model` ❌
- 多个相关项目可用家族名：`SegGrade-Model`、`SegGrade-DataPipeline`、`SegGrade-Deploy`

## 项目内结构模板
新项目可参考 `_Active/SegGrade-Model/` 的结构（含 12 个 _README.md）。
